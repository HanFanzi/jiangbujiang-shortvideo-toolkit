# [项目]反馈规范 V1.3

> 目的：统一「哪些节点必须反馈、谁反馈、写到哪、什么格式、怎么进知识库」，让各环节照着做。
> 口径来源：V1.8 §八、table-template.md 表3/表4/表5、05_知识库（02脚本规则 / 04错误案例 / 05反馈转规则台账）、ASSET-006/007/009、SCRIPT-011/012/013、SPEC §4/§11、用户拍板 2026-11-23（发布后ID回传 / 素材总清单）、用户拍板 2026-11-24（拍摄地点词表合并）。
> V1.3 相对 V1.2 的变更：审核环节三选一改四选一（补「分镜审核」，D22）；关联脚本ID改为脚本审核、分镜审核均必填；新增 A0「对标素材审核意见」定位（只写表2、不同步表4，D24）。V1.2 及更早版本保留不删。

## 结论先行

1. **三类审核反馈写表4**：脚本审核 / 素材审核 / 成片审核；表4「反馈与拍摄记录」是审核反馈唯一入口，一处事实只写一次。
2. **状态类就地写表3**：可拍摄判定、判定依据、拍摄状态、成片路径/验收反馈写表3，不在表4重复写同一条（V1.8 §八末段）。
3. **发布后ID由人工回传**：成片经门店发布后，人工把平台发布后ID回填表3「🔴成片路径/验收反馈」；`-RMnn` 只是本地临时ID，不得当发布ID（§三、§八）。
4. **优化归属决定去留**：`对标视频获取 / 脚本制作 / 素材整理` 三类进知识库候选；`不纳入`（含成片审核）只留记录不改规则。
5. **草稿不自动生效**：自动化只写反馈原文、规则草稿、状态；转生效必须人工确认并递增版本号（05_反馈转规则台账）。
6. **脚本审核、分镜审核必填关联脚本ID**：取表5「🟢关联作品ID」值，如 `[作品ID]-S01`（SCRIPT-012）。
7. **A0 对标素材审核单独记账**：用户填在表2「对标素材审核意见」，宽松归类可使用/需改写/不可用/延后；只写表2、不同步表4，不作为表4反馈记录，也不生成规则草稿（D24）。需改写退回人工改终版后重走 A0。

## 一、节点 → 反馈动作 → 字段 → 谁负责

| 节点 | 触发时机 | 反馈动作 | 写到哪 / 字段 | 谁负责 | 标记 |
|---|---|---|---|---|---|
| 对标获取 | 榜单宽匹配命中不相关作品、数据口径异常 | 表4脚本/素材审核带出，优化归属=`对标视频获取` | 表4 反馈内容/反馈人/优化归属 | 拆解人 | 🔴人工 |
| 拆解 | 拆解卡某判断无证据、口径存疑 | 写结果表对应卡片「无法证明的部分」，不改规则 | 结果表 md | 拆解人（AI出初稿） | 🟡AI初稿待确认 |
| 素材整理 | 下载失败、时长异常、可拍判定 | 失败/判定就地写表3；需沉淀的问题另写表4素材审核 | 表3 本地路径/时长/可拍摄判定/判定依据；表4 | 素材整理人 | 🔴人工 |
| **素材清单维护**（V1.1 新增） | 新增 / 移动 / 作废自有素材 | 同步更新 `素材名称总清单.csv`；需沉淀的问题写表4素材审核 | `02_自有素材/素材名称总清单.csv`；表4 审核环节=素材审核、优化归属=素材整理 | 素材整理人 | 🔴人工 |
| 脚本制作 | 依据闸门拦截、分镜要点不合规 | 终版空缺列待补清单；审核反馈写表4脚本审核 | 表4 关联脚本ID 必填；表5 制作状态/审核结果 | 脚本审核人 | 🔴人工 |
| 拍摄/复刻 | 拍摄状态推进、返工 | 状态就地写表3，复刻状态联动 | 表3 拍摄状态/复刻状态/🔴成片路径验收反馈 | 拍摄岗 | 🔴人工 |
| **发布后ID回传**（V1.1 新增） | 门店发布完成 | 人工把平台发布后ID回填表3；不写表4 | 表3「🔴成片路径/验收反馈」四要素 + 发布后ID | 人工回传岗 | 🔴人工 |
| 成片审核 | 成片完成待验收 | 表4成片审核留记录，优化归属=`不纳入` | 表4 全字段；表3 验收四要素 | 验收人 | 🔴人工 |
| **AI选素材失败**（V1.1 新增） | AI 按文件名+清单选错或匹配不到素材 | 写表4素材审核，说明是词表问题还是清单字段缺失 | 表4 审核环节=素材审核、优化归属=素材整理、反馈内容写明失败类型 | 素材整理人 / AI 初判 | 🟡AI初稿待确认 |
| 数据回传 | 拉数失败、复盘表字段缺失 | 记工作记忆，不进表4（本阶段只搭骨架，未产真实反馈） | 本地复盘表 / 工作日志 | 运维 | 🟡待确认 |

> 🟢/🟡/🔴 是表格字段标题的字面量前缀（数据契约标识），不是装饰图标。

## 二、表4必填与格式

| 字段 | 类型 | 填写规则 |
|---|---|---|
| 🟢反馈标题 | 文本 | 一行说清主题 |
| 🟢反馈ID | 自动编号 | 自增，不手填 |
| 🟢关联作品ID | 文本 | 平台作品ID；无对应作品可留空但不能整行空 |
| 🟢关联素材ID | 文本 | 取表3素材ID；素材清单类反馈写素材文件名 |
| 🟢关联脚本ID | 文本 | **脚本审核、分镜审核必填**，取表5「🟢关联作品ID」（如 `[作品ID]-S01`）；其他环节留空 |
| 🟡审核环节 | 单选 | 脚本审核 / 分镜审核 / 素材审核 / 成片审核，四选一 |
| 🟡审核结果 | 单选 | 通过 / 修改后通过 / 不通过 / 待反馈 |
| 🟡优化归属 | 单选 | 对标视频获取 / 脚本制作 / 素材整理 / 不纳入 |
| 🔴反馈人 | 文本 | 实际审核人姓名 |
| 🟢反馈日期 | 日期 | 13 位毫秒时间戳 |
| 🔴反馈内容 | 文本 | 问题、缺口、修改要求；写具体现象不写「优化体验」 |
| 🔴处理动作 | 文本 | 具体动作，如「补素材ID命名」「扩充景别词表」 |
| 🟡处理状态 | 单选 | 待处理 / 已采纳 / 已落地 / 不采纳 |
| 🟢落地版本 | 文本 | 例：`工作方法 V1.5`；未落地留空 |
| 🟢关联规则 | 文本 | 例：`SCRIPT-001`；无规则留空 |

**审核结果两表口径不同，不要混用**：表4 = `通过/修改后通过/不通过/待反馈`；表5「🔴审核结果」= `待审核/通过/需修改/不通过`。脚本审核在表4填结论，在表5同步对应状态。

## 三、表3状态类怎么填（本表就地，不写表4）

| 字段 | 怎么填 | 来源 |
|---|---|---|
| 🟡可拍摄判定 | 四问全满足=可拍；缺1项且补齐动作明确=有条件可拍；版权背书/纯海报/对方资历价格不可换/高成本剧情=不可拍 | ASSET-006 / V1.8 §八 |
| 🔴判定依据 | 写四问逐项结果 + 不可拍原因 | ASSET-006 |
| 🔴拍摄状态 | 未开始/待排期/拍摄中/已拍待验收/返工/已完成；任一完成条件缺失不得写已完成 | ASSET-007 |
| 🔴复刻状态 | 未复刻/复刻中/已复刻；拍摄状态进入拍摄中后同步改 | ASSET-009 |
| 🔴成片路径/验收反馈 | 四要素 `路径=...；验收结果=...；验收人=...；验收日期=...` + **平台发布后ID**（见下） | ASSET-008 / V1.8 §八 / 用户拍板 2026-11-23 |

**发布后ID回传写法（V1.1）**：成片交门店发布完成后，人工回传岗把平台实际返回的成片ID写入表3「🔴成片路径/验收反馈」，格式为：

```
路径=[项目根]/03_成片/{作品ID}-RMnn.mp4；验收结果=...；验收人=...；验收日期=...；发布后ID={平台实际ID}
```

- `-RMnn` 是本地临时内部ID，只用于混剪落盘与 sidecar 命名（SPEC §4 `[假设]`）；**不得填入「发布后ID=」位置**。
- 回传动作不写表4（非审核反馈）；若回传失败或ID异常，记工作日志交人工核对。

## 四、优化归属怎么选

| 问题出在 | 选 | 进知识库？ |
|---|---|---|
| 榜单筛不准、作品ID去重、官方统计口径、粉丝量抓取 | `对标视频获取` | 进候选 |
| 终版依据闸门、分镜要点、脚本版本、文案切片还原 | `脚本制作` | 进候选 |
| 素材ID命名、下载失败、抽帧、可拍判定、拍摄状态联动 | `素材整理` | 进候选 |
| **素材总清单漏登/错登/未同步、词表外取值、AI选素材选错或匹配不到** | `素材整理` | 进候选 |
| 成片观感、门店发布效果、一次性偶发问题、发布后ID回传异常 | `不纳入` | 不进；只留表4记录或工作日志 |

## 五、反馈怎么进知识库（生效闸门）

```
表4反馈（人工填）
   └─> 每日自动化筛选：汇总状态=待汇总或空 AND 处理状态∈{待处理,已采纳,已落地} AND 优化归属≠不纳入
        └─> 分流：一次性问题 → 写 04_错误案例库.md（不生成规则）
                  可复用问题 → 先查重（同环节同现象），生成规则草稿 → 写 05_反馈转规则台账.md
        └─> 人工确认草稿 → 生效 → 递增规则文件版本号 → 同步技能引用文件
```

**硬约束**（05_反馈转规则台账 + V1.8 §八）：
1. 自动化只写反馈原文、规则草稿、状态；**不直接改**规则、工作方法、结果表、Skill、知识库、三表。
2. 草稿转生效必须人工确认；未确认的「待确认」规则**不参与**脚本生成（SCRIPT-013）。
3. 同一问题改 3 轮不过 → 停手报人，不继续试（SCRIPT-013）。
4. 反馈处理完标「已汇总」并写处理时间；工作日志记录本次应用的规则ID，交付文档不写过程记录（V1.8 §八 / 00_索引）。

## 六、成片审核为何不进知识库

- **规则原文**：成片审核保留记录，但不进知识库（V1.8 §八）；成片审核不改规则（05_反馈转规则台账）。
- **理由**：成片问题多是单次观感/门店发布效果，一次性、不可复用为规则；且对标视频只作内部研究、不二次分发，成片标注「内部验证·不二次分发」，把成片问题沉淀成规则会把内部验证产物混入生产规则链。
- **做法**：表4填成片审核 + 优化归属=`不纳入`；验收四要素写表3「🔴成片路径/验收反馈」；不生成规则草稿、不进04错误案例库。发布后ID回传属回传动作，同样不进知识库（§三）。

## 七、脚本制作依据闸门（反馈时的硬线）

- 脚本**唯一依据**是表2「🔴人工修正文案（终版）」，人工定稿填入，AI 不代填；空值不生成，列待补清单（SCRIPT-013 / D08）。
- 禁止用「🟡改写文案」「🟡对标完整文案」或对标逐字稿顶替终版。已知反例：ERR-SCRIPT-005（终版全空仍产出 22 条，口播文案非人工定稿，无法追溯依据）。
- 终版逐字不改；原文逻辑不通只示警、不代改；分镜切片按顺序拼接必须等于终版原文。
- 脚本审核、分镜审核反馈必须填关联脚本ID，否则无法定位具体版本（六表校验第24项）。

**正例（成片审核 + 发布后ID回传，V1.1）**

表3再写（门店发布完成、人工回传后）：

**反例（不要这样写）**

```
审核环节：脚本审核，关联脚本ID留空        # 违反 SCRIPT-012，定位不到版本
反馈内容：体验不好，优化一下              # 无具体现象，无法转规则
优化归属：不纳入，审核环节=素材审核却写规则草稿  # 归属与动作矛盾

发布后ID=[作品ID]-RM01         # 把本地临时ID当平台发布ID
素材新增了但总清单没更新，只在表4写反馈    # 清单维护节点要求先更新清单，表4只记需沉淀的问题
```
