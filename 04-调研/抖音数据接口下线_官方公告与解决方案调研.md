# 抖音自有账号数据接口下线：官方公告与解决方案调研

## 结论

`28001056 该能力API已下线` 不是配置问题、不是密钥问题、不是测试应用限额问题，是抖音开放平台主动下线并回收了一批数据类能力。当前「网站应用 + 用户授权」这条链路拿不到自有账号的视频播放/点赞/评论/粉丝数据，且官方没有恢复时间表。

对应到本 skill：设计用的 scope `video.list.bind`、接口 `/api/douyin/v1/video/video_list/`，以及实测的 `/data/external/item/base/`、`/data/external/user/fans|like/`，全部落在公告 289 的回收清单里。三重锁死，继续重试或重新扫码都不会有结果。

按本轮口径，skill 文件未改动（SKILL.md、douyin_data.py 保持原状）。

公告 289 回收清单中与本任务直接相关的 scope：

| 能力 | Scope |
|---|---|
| 视频互动数据【视频数据】 | `data.external.item` |
| 用户互动数据【用户账号公开数据】 | `data.external.user` |
| 视频查询【抖音公开作品相关数据】/【抖音公开作品列表】 | `video.data` / `video.list` |
| 视频查询（经营能力）抖音指定作品公开数据 / 公开作品列表 | `video.data.bind` / `video.list.bind` |

289 有一条例外：带【】标识的 scope，历史已购买付费增值套餐的应用可继续调用至套餐有效期结束，到期失效。本应用为新建测试应用，无历史套餐，不适用该豁免。

口径待核：不同抓取结果对「历史已开通应用是否受影响」表述不一致（一处写「不受影响，可继续使用」，一处写「分批回收，历史开通过的将无法继续使用」）。以公告原文为准，此处标注未核实。

## 三、本应用踩到的三重锁

| 锁 | 现象 | 对应证据 |
|---|---|---|
| 🔴 接口物理下线 | 8 个数据接口统一 28001056 | 公告 289 于 2025-03-13 起回收 `data.external.item` / `data.external.user` / `video.list.bind`，回收后接口不再可用 |
| 🔴 新申请入口关闭 | 控制台能力管理翻遍内容能力 / 抖音业务能力 / 个人资料三页都找不到 `video.list.bind` 申请入口 | 289 自 2025-02-13 停止接收新增申请；官方「视频数据管理」能力页标注「能力改造中，暂不开放申请，详情请参考平台公告」；2024-09 官方客服口径「改造中，无明确更新计划」 |
| 🔴 授权拿不到 scope | 授权成功返回 `scope=user_info,trial.whitelist`，授权页权限列表只有「获取用户公开信息」「把你添加进测试应用白名单」 | 与锁 2 一致：`video.list.bind` 当前不在可授权范围 |

补充：`/api/apps/v1/video/query/`、`/api/apps/v1/item_bc/get_play/` 属于**小程序应用**的 `ma.video.bind` / `ma.item.data_bc` 体系，用网站应用的 `act.xxx` token 调不通，此前实测「无有效返回」即此原因，不是接口本身可用。

官方「视频数据管理」能力页仍写着「唯一官方认证的对外开放的抖音数据」，但适用范围一栏明确「能力改造中，暂不开放申请」，应用类型限定移动应用和网页应用，scope 仍是 `data.external.item`。2023—2026 连续 6 份回收公告方向是持续收紧，不是回归。

## 四、解决方案清单

| 色标 | 方案 | 能拿到的数据 | 前置门槛 | 判定 |
|---|---|---|---|---|
| 🔴 | A 等官方恢复「视频数据管理」 | 恢复后同原 OpenAPI | 无时间表，官方只承诺「有明确更新计划后提前 1 个月发公告」 | 不可控，不作主线，只订阅公告 |
| 🟠 | B 另建小程序应用 + 用户数据能力 / 经营矩阵 business_token | 30 天内视频的播放/点赞/评论/分享、抖音主页数据、视频评论列表 | 企业开发者；新建小程序应用；控制台申请 `ma.video.bind` / `ma.item.data` / `ma.video.bind_bc` / `ma.item.data_bc`（能否批未验证）；完成抖音企业机构号绑定「近30天视频数据查询」；账号在抖音端走「创作者服务中心 → 开通数据看盘能力 → 立即开通」；经营关系授权后调 `/business_token/` 生成 `bus_act.xxx`；旧小程序企业号（品牌号/员工号/合作号）绑定入口正在下线 | 官方合规但改造量大、只给 30 天内视频、首次授权次日才出数、官方仍在改造，当前不投入 |
| 🟢 | C 创作者后台 / 企业号后台导出 | 官方全口径后台数据：播放、完播、流量来源、粉丝、互动，creator.douyin.com 数据中心支持导出表格 | 多账号逐个登录、人工导出 | 数据最准、零合规风险、零成本，先把「分析 → 出方案」跑通 |
| 🟡 | D 浏览器登录态自建采集 | 同 C，但自动化 | 维持登录态、页面改版要跟、有验证码 / 指纹 / 访问量风控 | 可控、零额外付费，补「自动收集」这一环 |
| 🟡 | E RPA 采集（影刀 X 飞书方案） | 图文/视频/评论/主页数据、企业号内容管理与私信、罗盘、千川、抖店 | 付费、浏览器登录态、风控与维护 | 影刀官方 wiki 明写「开放平台 2025-03-13 起关停视频/评论/直播管理接口，集成模板失效，RPA 不受接口限制」，对口「矩阵号多账号数据整合、分析、报告推送」，规模化备选 |
| 🟠 | F 第三方按量数据 API（DataXAPI 等） | 公开视频/账号/评论/热榜，按次付费、无需抖音账号 | 付费 | 只覆盖公开数据、第三方抓取估算非后台结算口径，限定用于对标/竞品（与现有红狐 HUB 定位一致），不作自有账号主口径 |

来源：B/C/D/E/F 判定均为 C 联网检索（官方文档页、影刀飞书 wiki、第三方服务商文档）；本 skill 相关实测为 B 工具实测。第三方 RPA 与 API 的稳定性数值（如可用率、中位耗时）来自服务商自述，标未核实。

## 五、推荐路径

1. 用 C 把后半段链路跑通：多账号各导出一份创作者后台数据，验证「数据回传 → 系统分析 → 运营方案」的口径和报告模板。
2. 自动收集用 D 补位：浏览器登录态读后台导出，跑通「多账号 → 汇总 → 入库」。
3. E 作为规模化备选，账号量和采集频次上来后再评估付费与维护成本。
4. B 只在「必须走官方合规 API，且接受另建小程序应用 + 企业机构号绑定」时才启动，第一步先到控制台核实「视频数据查询」能力是否仍可申请。
5. F 限定对标/竞品数据。
6. A 挂起，保留公告订阅。
