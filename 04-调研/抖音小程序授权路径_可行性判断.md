# 抖音小程序授权路径：可行性判断

## 结论

🔴 这条路当前仍走不通。`tt.showDouyinOpenAuth` + `ma.user.data` / `ma.video.bind` / `ma.item.data` / `ma.item.comment` 属于**小程序应用**体系，跟已跑通的**网站应用**体系是两套：凭证换成小程序 `appId + APP Secret`，授权入口换成抖音 APP 内真机弹窗，能力目录换成「能力 > 用户数据能力 > 抖音账号数据」，服务端接口换成 `/api/apps/v1/...`。当前应用「匠不匠数据整理」是网站应用、测试应用状态，文档接口页明确写「测试应用无法申请该权限」。已跑通的 `client_key/client_secret`、网页扫码 OAuth、备案域名 `[域名]`、已绑定的 `act.xxx` 一套都用不上。

🟢 控制台实测修正（2026-11-27，见第八节）：小程序应用**已经存在**（AppID `[AppID]`），「能力 > 用户数据能力 > 抖音账号数据」入口**也在**，不是「改造中 / 暂不开放申请」，有明确申请条件与申请按钮；「视频数据查询」显示**已开通**。这扇门没被公告 289 关上，是开着的。不用另建小程序。

🔴 但进门前一整套没做完：小程序待完成备案、基础信息「已过期」、未设置主营类目、待上传版本、未上线。控制台直接标「**暂不满足申请条件**」，「申请开通」置灰；未上线就没法在抖音 APP 内真机调起授权弹窗，拿不到 `ticket` → 换不到 `act.xxx`，取数链路起不来。「授权」页当前「暂无相关能力」。

🟡 数据口径有边界（千粉以上、30 天内视频、T+1、单次授权单场景 ≤3 scope）。文档列的 4 个 scope，控制台「抖音账号数据」tab 只列 2 个能力，`ma.user.data` / `ma.item.comment` 未出现；能力标识也换成 `ma.openapi.*` 命名。

来源分级：A 用户材料（2026-11-26 粘贴的官方说明）；B 工具实测（2026-11-27 官方页抓取、限定官方域名检索命中 5 条官方接口页；2026-11-26 `28001056` 取数实测）；C 联网检索（公告 289、能力页）；D 模型知识（本轮不采信）。

## 三、四个硬门槛

🔴 **应用类型换了**。接口页「权限要求」原文：「需通过控制台-**小程序应用**下，进入『能力-用户数据能力-抖音账号数据』，申请『近 30 天视频数据查询』能力权限」。网站应用「匠不匠数据整理」菜单路径不同，不能就地加权限。控制台另有小程序应用 `[AppID]`，该菜单实测存在（第八节）。

🔴 **测试应用申不了**。`获取用户视频情况`、`获取用户粉丝数` 接口页接口说明首句：「测试应用无法申请该权限」。网站应用「匠不匠数据整理」仍是测试应用状态（页面曾提示「直至 03.18 调整为 0 次/天」）。控制台「抖音账号数据」tab 未见 `ma.user.data` 能力，此条无法在现有小程序上验证。

🔴 **授权必须人手动、必须在手机上**。`tt.showDouyinOpenAuth` 是小程序内弹窗，只在抖音 APP 内调起，模拟器不支持、沙盒否。要真机调起还得先有一个已发布的抖音小程序；实测该小程序「待上传版本」「待完成小程序备案」「昨日数据：需上线后展示」，未上线。当前「自动收集多个账号数据」的首次授权环节做不到无人值守，每个账号每次都要本人点同意。

🔴 **能力要先审批开通**。控制台申请 → 审批通过 → 才能在授权弹窗里勾选；未开通直接报 `117405 no usage scope`。入口已实测存在，但当前「暂不满足申请条件」、「申请开通」置灰（第八节）。

## 四、数据口径边界（接口页原文，B）

| 限制 | 原文 | 影响 |
|---|---|---|
| 粉丝门槛 | 「只返回千粉以上用户的数据」（`ma.user.data` 系列） | 千粉以下账号取不到主页数据 |
| 数据延迟 | 「用户首次授权应用后，需要第二天才会产生全部的数据；后续的数据会在第二天十点左右刷新」 | 首次授权当天无全量数据 |
| 视频时效 | 「三十天内创建的视频，才会返回数据」（`get_base/`）；「返回从昨天开始过去 n 天的数据，不包括当天」 | 历史作品、当天数据取不到 |
| 授权拆分 | 单次授权仅一种场景、scope ≤ 3 | 主页数据（场景一 1 个）+ 视频数据（场景二 3 个）要分 2 次授权 |
| 测试期 | 测试应用限额按 scope 每日 100 次递减 | 与现有网站应用测试期同类问题 |
