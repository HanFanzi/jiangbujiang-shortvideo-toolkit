# 重做小程序走官方授权：能不能拿到账号数据（前置判断）

## 结论

🔴 走你贴的那份 `tt.showDouyinOpenAuth`（**普通抖音号授权**，`act.xxx`）：**能取到数，但取不全，而且自动不起来**。能拿账号近 7/15 天按日汇总，以及**已知 item_id 的**单条视频明细；这套接口里**没有「列出账号作品」的能力**，拿不到 `item_id` 就无法枚举一个账号的全部作品。加上千粉以上、30 天内、T+1、每账号每次本人进抖音 APP 手动点同意。

🟢 要拿全（作品列表 + 逐条播放/点赞/评论/分享 + 主页 + 评论）且要自动跑多账号，得走**经营矩阵**：企业机构号绑定 + `client_token` / `business_token`。官方能力清单里明确有「查询作者视频列表」，且 `business_token`「可以由开发者自行签发」，绑定关系建好后取数不需要每次弹窗。员工号 50 个、合作号 200 个，覆盖多账号。

🔴 两条路共用一个未实测的决定性风险：`/api/apps/v1/...`、`/aweme/v1/video/self/...` 这组接口**当前是否还在线、是否同样返回 `28001056`**。公告 289 / 462 下线的是「移动/网站应用」的 `/api/douyin/v1/...`、`/data/external/...`，没查到针对小程序数据能力的下线公告，控制台也确实有「已开通」能力；但文档在 ≠ 接口在，这一条只能实测。

一句话回答：**能，但不是靠 `tt.showDouyinOpenAuth` 那条；要换经营矩阵，且先花一次实测确认接口还活着。**

来源分级：B 工具实测（2026-11-27 官方接口页 / 公告检索抓取、控制台只读盘点）；C 联网检索（公告 289 / 427 / 462、能力页）；D 模型知识（本轮不采信）。

## 一、两套授权别混

| 项 | 普通抖音号授权 | 经营关系授权 |
|---|---|---|
| 入口 | `tt.showDouyinOpenAuth` 小程序内弹窗 | 控制台绑定品牌号 / 员工号 / 合作号 + 用户授权绑定关系 |
| 凭证 | `act.xxx`，`/oauth/access_token/` 生成 | `clt.xxx`（`/oauth/client_token/`）、`bus_act.xxx`（`/oauth/business_token/`） |
| Scope | `ma.user.data`、`ma.video.bind`、`ma.item.data`、`ma.item.comment` | `ma.self_mount_video.item_list`、`ma.user.data_bc`、`ma.item.data_bc`、`ma.video.bind_bc`、`ma.business_token` |
| 接口 | `/api/apps/v1/user/get_item/`、`/api/apps/v1/item/get_base/`、`/api/apps/v1/video/query/` | `/aweme/v1/video/self/get_user_video_list/`、`/api/apps/v1/item_bc/get_base/`、`/api/apps/v1/item_bc/get_play/`、`/api/apps/v1/video_bc/query/` |
| 开发者类型 | 无特殊要求 | **企业开发者** |
| 作品列表 | ❌ 没有 | ✔️ 查询作者视频列表 |
| 多账号 | 每个账号单独扫码授权 | 员工号 50 / 合作号 200 |
| 取数是否每次弹窗 | 是 | 否（`business_token` 开发者自行签发，依据：官方 BusinessToken 生成页原文，未端到端实测） |

控制台现有小程序 `[AppID]` 已开通的能力标识是 `ma.openapi.video.bind_bc`，带 `_bc`，属于**经营版**，不是普通授权版 `ma.video.bind`。该主体已经触达过经营体系。

## 二、普通授权能拿到什么（官方接口页响应字段，B）

| 接口 | Scope | 返回内容 |
|---|---|---|
| `/api/apps/v1/user/get_item/` | `ma.user.data` | `result_list`：`date`、`new_issue`、`new_play`、`total_issue` —— **按日汇总，没有 item_id / 作品列表** |
| `get_fans/` / `get_like/` / `get_comment/` / `get_share/` / `get_home_pv/` | `ma.user.data` | 近 7/15 天按日数值 |
| `/api/apps/v1/item/get_base/` | `ma.item.data` | `result`：`total_play`、`total_like`、`total_comment`、`total_share`、`avg_play_duration` —— **单条作品明细** |
| `/api/apps/v1/video/query/` | `ma.video.bind` | POST，Body 传 `item_ids` 或 `video_ids` 数组，返回实时点赞/播放数 |

🟠 缺口：`get_base/` 必填 `item_id`，文档原文「仅能查询 access_token 对应用户上传的视频」，且 `item_id` 要通过 `/api/apps/v1/convert_video_id/video_id_to_open_item_id/` 转换；`video/query/` 也要先有 ID。**这套接口没有任何一个返回账号的作品列表**，所以自动收集必须从别处先拿到每条作品的 ID。

🟠 `open_id` 两个来源：普通授权走 `/api/apps/v2/jscode2session`（code2Session），经营授权的 `business_token` 也可取「移动网站应用通过 `/oauth/access_token/` 返回的 open_id」。小程序里首次仍需一次 `tt.login`。

## 三、经营矩阵才是完整链路（B）

能力概览（官方「小程序经营矩阵账号介绍」页，品牌号 / 员工号 / 合作号三列全 ✔️）：

| 能力 | 支持 |
|---|---|
| 查询作者视频列表 | ✔️ ✔️ ✔️ |
| 近30天视频数据查询 | ✔️ ✔️ ✔️ |
| 视频数据查询 | ✔️ ✔️ ✔️ |
| 视频评论数据 | ✔️ ✔️ ✔️ |
| 抖音主页数据 | ✔️ ✔️ ✔️ |

链路：

| 步 | 凭证 | 接口 | 拿到什么 |
|---|---|---|---|
| 1 | `clt.xxx`（`/oauth/client_token/`，scope `ma.self_mount_video.item_list`） | POST `/aweme/v1/video/self/get_user_video_list/` | `user_publish_item_list`：`create_time`、`item_id`、`video_link`；参数 `aweme_id`（作者抖音号）、`count` ≤100、`cursor`（30 天内毫秒时间戳） |
| 2 | `bus_act.xxx`（`/oauth/business_token/`） | GET `/api/apps/v1/item_bc/get_base/`、`item_bc/get_play/` 等 | 每条作品的播放/点赞/评论/分享 |
| 3 | `bus_act.xxx` | POST `/oauth/business_scopes/` | 查经营关系当前状态 |

`BusinessToken 生成` 页原文：「经营 Token 是面向经营关系场景内 OpenAPI 调用的鉴权工具。**可以由开发者自行签发**」；参数 `client_key` 填 AppID，`client_secret` 取「开发-开发配置-Webhook 页面的 Webhook AppSecret」（**不是**密钥管理的 AppSecret），`open_id` + `scope`（示例 `ma.user.data_bc,ma.item.data_bc`）。开发者类型：企业开发者。

`get_user_video_list` 接口说明原文：「调用方是小程序的开发者/代开发」「视频作者 ID 有授权给小程序『查询作者视频列表』能力」「**需要用户授权绑定关系**」「此能力需使用 client_token」。

## 四、硬边界

| 级别 | 项 | 原文 / 依据 |
|---|---|---|
| 🔴 | 30 天窗口 | 列表「用户发布**三十天内**的公开视频列表」、`cursor` 限 30 天内；明细「**三十天内创建的视频**，才会返回数据」；主页近 7/15 天「不包括当天」 |
| 🔴 | T+1 | 「用户首次授权应用后，需要第二天才会产生全部的数据；后续的数据会在第二天十点左右刷新」 |
| 🟠 | 千粉门槛 | `ma.user.data` 系列「只返回千粉以上用户的数据」 |
| 🟠 | 测试应用 | `get_item/` 接口说明首句「测试应用无法申请该权限」——**重做的新小程序不能停在测试应用状态** |
| 🟠 | 只公开视频 | 「只返回用户公开的视频数据，未公开的视频数据不会返回。如果视频设置为了隐私，则返回创建时间为 0 的记录」 |
| 🔴 | 公告 427 | 小程序旧企业号创建及绑定入口 **2026-02-02 下线**；历史已绑定未迁移的，**2026-03-01 起陆续回收**已授权能力；要求 2026-02-28 前完成迁移。当前 2026-11-27，必须走新的「抖音企业机构账号」体系 |
| 🟠 | 类目 | 2025-01-23 小程序搜索能力公告把「工具 > 营销工具 > 互动营销」列入不再支持新增申请的范围（针对搜索能力，不是数据能力）；现有小程序服务类目正是这一类目，重做时建议换类目确认 |
| 🔴 | 上线前置 | 备案 + 设主营类目 + 发版上线审核仍是硬门槛，约 1 个月，见 `小程序合规路径_补齐清单.md` |

公告 289（2025-02/03）、462（2026-05/06）标题均为「**移动/网站应用**的部分能力下线回收公告」，回收清单不含 `ma.*`；本轮未检索到针对小程序 `ma.*` 数据能力的整体下线公告。

## 五、做之前必须先验证的 5 项

| 项 | 为什么必须先验证 | 怎么验 |
|---|---|---|
| 接口是否在线、是否也返回 `28001056` | 决定性。文档在 ≠ 接口在，公告 289 已证明「文档还挂着但接口物理下线」会发生 | 用有效 `bus_act.xxx` 发一次 `/oauth/business_scopes/` 或 `/api/apps/v1/item_bc/get_base/` 看返回 |
| 主体能否开通抖音企业机构账号并完成绑定 | 经营矩阵全部能力的前提 | 控制台看企业机构账号入口与绑定状态 |
| 新小程序能否申请到全套经营能力 | 控制台「抖音账号数据」tab 当前只列 2 个能力，`ma.user.data` / `ma.item.comment` 未出现 | 新建小程序后逐项看「能力 > 用户数据能力」与经营矩阵能力页 |
| 主营类目定哪个 | 影响能力申请范围 | 对照经营权限类目表确认 |
| scope 命名混用 | 控制台 `ma.openapi.*`、文档 `ma.*`、经营状态查询响应示例 `video.list.bind` / `video.data.bind`（旧名），官方自身不一致 | 以控制台实际可勾选的项为准，未核实映射 |

## 六、最小验证方案（不等整个小程序上线）

现有小程序 `[AppID]` 已开通 `ma.openapi.video.bind_bc`，可作探针：

1. 控制台确认该小程序的企业机构账号绑定入口与状态（「授权」页当前「暂无相关能力」）。
2. 若可生成 `business_token` → 用 `client_key`(AppID) + Webhook AppSecret + `open_id` 签发 `bus_act.xxx`。
3. 发一次 POST `/oauth/business_scopes/`，再发一次 GET `/api/apps/v1/item_bc/get_base/`（带任一 item_id）。
4. 返回 `28001056 该能力API已下线` → 整条官方路线作废，直接回 `douyin-data-mcp`（创作者后台登录态只读、零依赖、Chrome CDP 9333）。
5. 返回正常数据或参数类错误 → 接口活着，再决定要不要投备案 + 发版。

官方各接口页带「在线调试」入口，可辅助验证。
