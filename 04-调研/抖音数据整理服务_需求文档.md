# 账号数据整理与可视化报表需求文档

**结论**：对标和同行数据前期不做。首期只做抖音账号授权管理、数据整理、可视化报表和分析建议，并由 AI 大模型参与数据归类、报告成文和分析解读；后续再接小红书、快手、视频号、知乎等平台。AI 不替代官方接口取数，所有结论必须能追溯到原始指标。收费采用充值积分、按次扣费；用户后台看余额和流水，管理员后台管积分规则和成本定价。核查日期 2026-11-18。

## 一、范围与边界

| 问题 | 解法 | 状态 | 依据 |
|---|---|---|---|
| 用户要整理自己账号的数据 | 用户扫码授权本人账号，系统按 scope 拉取，生成可视化报表和下载文件 | 首期做 | S1、S2 |
| 用户要管理授权给本网站的账号 | 自有账号体系提供绑定、解绑、授权状态、权限范围、失效提示 | 首期做 | S6、S11 |
| 后台分几套 | 用户后台 + 管理员后台，权限和数据可见范围分开 | 已确认 | S14、S15 |
| 同行和对标数据 | 前期不做，不写入本期开发范围 | 排除 | S8、S9、S10 |
| 报表要带分析和建议 | 规则判断 + AI 解读，基于本账号历史指标输出趋势、占比、异常提示 | 首期做 | S12、S13 |
| AI 大模型介入范围 | 做数据清洗归类、报告成文、分析建议；不做账号操作、不替代取数接口 | 首期做 | S13 |
| 大模型费用怎么收 | 用户先充值积分，生成报告或分析时预扣，成功实扣、失败退回 | 已定方向，比例待确认 | S15 |
| 收多少怎么定 | 按模型 token 成本 + 接口/服务器/支付分摊 + 目标毛利率计算，再换算积分 | 公式已定，参数待确认 | S15 |
| 一次授权多个抖音账号 | 不支持批量勾选；逐个扫码，每个账号一条授权记录 | 规则确定 | S6 |
| 同一自然人的多个抖音账号归并 | 平台无官方归并标识；用自有 `user_id` 串联多条 `open_id` | 规则确定 | S7 |
| 后续接其他平台 | 抖音完成后再评估小红书、快手、视频号、知乎；各平台授权方式、接口、资质逐平台核查 | 后续阶段 | S12 |
| 行业角色选什么 | 当前不认证。现有角色只有生活服务商家、生活服务MCN机构，适用生活服务与泛知识解决方案 | 不认证 | S4、S5、S11 |

## 二、用户与账号体系

| 问题 | 解法 | 规则 |
|---|---|---|
| 网站用户怎么标识 | 注册用户用自有 `user_id` | 与平台账号体系解耦 |
| 一个用户绑定多个平台账号 | `user_id` 1:N `(platform, open_id)` | 首期 `platform=抖音`，后续加平台不改用户主键 |
| 授权记录怎么唯一 | 唯一键 `(platform, app_key, open_id)` | 抖音 `app_key=client_key`；`open_id` 只在当前应用内唯一 |
| 同一平台账号重复授权 | 按 `(platform, app_key, open_id)` 更新 token、scope、过期时间 | 不新建重复记录 |
| 账号管理界面展示什么 | 平台、昵称、头像、授权状态、已授权 scope、最近同步时间 | 用户提供解绑入口 |
| 能不能用 `union_id` 当主键 | 不能 | `get-access-token` 响应示例未给 `union_id`；未绑定开发者账号没有该字段 |
| token 存哪里 | 只存服务端，加密保存 | `client_secret` 不落前端 |
| token 过期怎么办 | `access_token` 15 天，`refresh_token` 30 天；过期走刷新或重新授权 | 响应字段 `expires_in=1296000`、`refresh_expires_in=2592000` |
| 用户解绑怎么办 | 自有授权表标记失效，停止拉取 | 不依赖平台自动通知 |
| 多平台扩展怎么存 | 授权表预留 `platform`、`app_key`、`account_type` 字段 | 不把抖音字段写死成全局字段 |

## 八、后台管理

后台分两套：用户后台管自己的账号、积分、余额、流水、报表和下载；管理员后台管用户、授权记录、任务、模板、AI 配置、积分规则、订单和日志。管理员后台不代用户授权，不展示 token 明文。

### 8.1 用户后台

| 问题 | 解法 | 状态 |
|---|---|---|
| 用户看自己绑了哪些账号 | 平台、昵称、头像、授权状态、已授权 scope、最近同步时间 | 必备 |
| 用户换账号 | 解绑旧账号→重新扫码授权新账号 | 必备 |
| 用户看授权失效 | 标注过期、 revoked、权限不足，给重新授权入口 | 必备 |

| 用户看积分余额 | 首页常驻显示当前积分余额、冻结积分、累计充值 | 必备 |

| 用户看发票申请 | 订单列表可申请发票 | 待确认 |

### 8.3 后台权限边界

| 问题 | 解法 |
|---|---|
| 谁能进后台 | 角色和账号待确认；按最小权限开通 |
| 后台能否看用户原始数据 | 默认不能；确需查看时按工单审批并留痕 |
| 后台能否改原始数据 | 不能；只能重跑任务，不直接改接口返回值 |
| 后台能否代用户授权 | 不能；每个平台账号必须由本人扫码授权 |
| 后台能否看 token | 不能；token 只存服务端加密字段，后台界面不展示 |
| 关键操作怎么控制 | 停用账号、删除数据、改模板、改 AI 配置需二次确认并写日志 |
| 后台导出数据 | 需审批、留痕，导出文件带操作人和使用目的 |

### [数值] 积分与定价

| 问题 | 解法 | 状态 |
|---|---|---|
| 大模型费用向谁收 | 向发起报告或分析的用户收，按积分扣；充值人即使用人 | 已确认 |
| 怎么扣 | 生成前预扣预估积分；成功按实际消耗结算；失败全额退回 | 已定 |
| 积分从哪来 | 用户充值获得；套餐和兑换比例由管理员配置 | 比例待确认 |
| 报告怎么分档 | 按报告类型设固定积分档，按实际 token 月度校准 | 待确认 |
| 余额不足 | 阻止生成，提示充值 | 必备 |
| 扣费争议 | 流水保留任务 ID、模型版本、输入/输出 token、积分变动 | 必备 |
| 管理员怎么改价 | 改模型单价、毛利率、积分档位需二次确认并留痕 | 必备 |
| 已生成报告是否补扣 | 调价不追溯已生成报告 | 硬约束 |

定价公式：

| 项目 | 计算 |
|---|---|
| 模型输入成本 | 输入 token × 模型输入单价 |
| 模型输出成本 | 输出 token × 模型输出单价 |
| 单次 AI 成本 | 模型输入成本 + 模型输出成本 |
| 单次服务成本 | 单次 AI 成本 + 接口调用分摊 + 服务器/存储分摊 + 支付通道费 |
| 单次售价 | 单次服务成本 ÷ (1 - 目标毛利率) |
| 积分单价 | 充值金额 ÷ 到账积分，由管理员配置 |
| 应扣积分 | 单次售价 ÷ 积分单价 |

模型单价取供应商实际报价，模型未定前不填具体数字。

本节依据 S14、S15。

## 九、非功能需求

| 问题 | 解法 |
|---|---|
| 凭证泄漏 | `ClientKey`、`ClientSecret`、`access_token`、`refresh_token`、模型 API Key 只存服务端，前端不接触 |
| 过度索取数据 | 只申请业务需要的 scope；用户端一次授权不超过 3 项 |
| 数据用途不清 | 用户协议写明采集字段、AI 使用范围、用途、存储期限、删除方式 |
| 接口转售风险 | 不共享、转售、转授权平台接口；每个平台账号必须由本人授权 |
| 测试态限额 | 先小量验证；上线前申请转正和能力提额 |
| 操作追溯 | 记录授权时间、拉取时间、scope、导出时间、平台、账号 `open_id` |
| 失败提示 | 私密账号、粉丝不足、授权过期分别给明确提示 |
| 分析可解释 | 每条建议带依据指标、判断阈值、数据时间范围、模型版本 |
| 模型输出校验 | 数字与官方返回或规则计算不一致时拦截，不展示 |
| 扣费准确 | 预扣、实扣、退回三段流水；积分和金额可逐笔核对 |
| 价格变更 | 管理员改价需审批留痕，不影响已生成报告 |
| 服务器地域 | 当前使用香港服务器，上线前确认数据出境合规；国内服务器路径更清晰 |

## 十一、风险与约束

| 等级 | 问题 | 解法 |
|---|---|---|
| 🔴 高风险 | 用户授权数据送境外模型触发数据出境 | 模型部署地域待确认；未完成合规确认前不接入境外模型 |
| 🟠 中高风险 | 行业角色发起后暂不支持更换 | 当前不认证；确需认证时先确认业务类目 |
| 🟠 中高风险 | 香港服务器触发数据出境判断 | 上线前完成合规确认 |
| 🟡 中风险 | AI 幻觉导致建议失真 | 数字只取接口和规则结果；建议带依据指标和阈值 |
| 🟡 中风险 | 模型调用成本不可控 | 按报告次数和 token 设上限，超限提示 |
| 🟡 中风险 | 测试应用有每日调用上限 | 先验证流程，上线前转正、提额 |
| 🟡 中风险 | 粉丝画像要求粉丝>100，授权后 2 天出数 | 前端提前提示，不做即时承诺 |
| 🟡 中风险 | 其他平台接口和授权机制未核查 | 逐平台立项，核查后再承诺能力 |
| 🟡 中风险 | 后台越权查看用户数据 | 默认不展示原始数据；查看需审批留痕；token 全程不展示 |
| 🟡 中风险 | 定价低于实际模型成本 | 按成本公式定价；设 token 上限；月度校准积分档位 |
| 🟡 中风险 | 扣费争议 | 三段流水 + 任务 ID + token 明细 + 调价不追溯 |
| 🟢 低风险 | 对标数据已排除 | 本期不排期，不产生第三方采购成本 |
| 🟢 低风险 | 主体资质和对公认证已有效 | 可直接创建抖音网站应用 |
