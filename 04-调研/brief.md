## 2. 复刻混剪前置依赖

### 2.1 输入素材从哪来

| 来源 | 现状 | 数量/口径 | 判定 |
|------|------|----------|------|
| 现有 22 条对标视频 | `[项目根]/01_对标素材/`，无水印源已落地 | 22 个 mp4、22 张拼图，共约 842 MiB（本机 ls 实测 2026-11-23）[FACT] | ✅ 可用于链路验证，仅内部研究，不二次分发（V1.8 §七第 3、6 条） |
| 自有素材 | `[项目根]/02_自有素材/` **空目录** | 0 个文件 [FACT 本机 ls] | ❌ 未就绪。用户口径：门店拍片头 + 我方拍产品/工厂视频；且素材命名混乱待治理 [FACT team-lead 转述]；本机 `03_成片/` 亦为空 [FACT] |

**命名混乱已实证**：现有文件名为纯作品ID（如 `[作品ID].mp4`），而 ASSET-001 规则要求 `素材ID_作品ID.mp4`，V1.8 §七第 6 条也写 `{素材ID}_{视频ID}.mp4`——**规则与实际落盘不一致**。[FACT 本机文件名 + 规则原文] 命名治理列为独立前置任务，不阻塞本次混剪链路验证（验证脚本可直接按作品ID 定位文件）。

### 2.2 本机 ffmpeg 能力边界（实测，非文档推断）

`ffmpeg 9.0.2`，`~/.local/bin/ffmpeg`，编译含 `--enable-gpl --enable-libx264 --enable-libx265 --enable-libass --enable-libfreetype --enable-libfontconfig --enable-videotoolbox`。[FACT `ffmpeg -version` 2026-11-23]

| 能力 | 实测结论 | 证据 |
|------|---------|------|
| 拼接 | ✅ 可用 | `concat` 滤镜存在；构造两段 1 秒测试流跑 `concat=n=2` 退出码 0 [FACT] |
| 转场 | ✅ 可用 | `xfade` 滤镜存在；跑 0.5 秒 `fade` 转场退出码 0 [FACT] |
| 字幕（硬字幕烧录） | ⚠️ 可用但有字体前提 | `subtitles`/`ass`/`drawtext` 滤镜均在，`--enable-libass` 已编入；`drawtext` 英文测试退出码 0 但报 `Fontconfig error: Cannot load default config file` [FACT]。中文字体 `fc-list :lang=zh` 返回 **0**，但系统有 `Hiragino Sans GB.ttc`、`STHeiti Light.ttc`、`STHeiti Medium.ttc` [FACT 本机实测] → **烧录中文字幕必须显式 `fontfile` 指向上述 ttc，不能依赖字体名自动查找**，否则中文渲染失败。这是最小混剪形态的唯一硬前提。 |
| 水印 | ✅ 可用 | `overlay` 滤镜存在，可叠加图片/文字水印 [FACT] |
| 抽帧/看片 | ✅ 已验证 | `fps`+`tile` 已用于现有 22 张 3×3 拼图 [FACT V1.8 + 本机文件] |

**边界**：ffmpeg 只做剪辑/合成，**不做**发布、不做账号取数；`subtitles` 滤镜吃 SRT/ASS 外挂字幕，需先有字幕文件（本次可从表2 文案或表5 口播文案生成，但终版列全空——见 §5 风险 R1）。

### 2.3 最小可跑通混剪形态

用 1 条现有对标视频（建议选 ≤60 秒的，如 `[作品ID].mp4` 虽 110 秒需裁剪）：截取 15–60 秒片段 → 拼 2–3 段 → 段间加 1 处 `xfade` 转场 → 烧录 1 条中文硬字幕（显式 `fontfile=/System/Library/Fonts/STHeiti Medium.ttc`）→ H.264 编码输出 MP4 到 `03_成片/`。输出用 ffprobe 读时长/分辨率验证。**不接片头、不接自有产品/工厂素材**（该素材为零，接入即阻塞）。[INFER 基于 §2.2 实测]

### 2.4 卡点

- **版权与用途**：对标视频只作内部研究，不二次分发；学习手法不搬运成片（V1.8 §七第 3 条）。本次成片必须标注「内部验证·不二次分发」，不得进发布链路。[FACT 规则原文]
- **终版列缺口**：若混剪字幕取自终版文案，则 0/117 全空会卡住——规避见 §5 R1（字幕改用拆解阶段已有口播文案做验证，不触碰终版口径）。

### 3.3 无凭证能否用模拟数据验证链路

**能，但只验证链路不验证数据源。**[INFER] 构造一份符合复盘表字段的模拟数据（作品ID/点赞/评论/收藏/分享/完播/日期），跑通「数据源接口 → 结构化映射 → 复盘表输出 → 标注模拟」四步，即可证明回传链路本身可用；真实取数需门店授权后单独验收。此项等价于机会验证里的「手工代跑」——先证明流程能跑，再接真实凭证（`opportunity-validation.md §四`）。
